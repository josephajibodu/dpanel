description: "Add your own Nginx or Caddy configuration to a site, with checks before applying and full history."

flitops writes a working web server configuration for every site and domain. When you need something extra, such as a redirect, a custom header, a larger upload limit or a reverse proxy, add it on the site's **Web Server** tab without logging in to the server.

Editing needs the **Manage sites** permission. Everyone in the team can view the files.

## How files are organised

flitops writes one **main configuration** per domain. It is rebuilt from the site's settings (PHP version, web directory, HTTPS, www redirect) every time one of them changes, so it is **read-only**: you can open it to see exactly what is running, but you don't edit it.

Your own configuration lives in separate files that the main configuration includes. This works the same way on Nginx and Caddy. Files are grouped by **domain**, and each one goes in one of two places:

| Where it goes | What it means | Use it for |
| --- | --- | --- |
| **Inside the site block** | Added to the site's own block (`server { … }` in Nginx, the site's `{ … }` in Caddy). This is the one you'll want most of the time. | Headers, redirects, upload limits, `location` rules, reverse proxies. |
| **Outside the site block** | Placed beside the site's block. For advanced setups. | Nginx `map`, `upstream` and rate-limit zones, or an extra block for another address. |

Because your files are kept apart from the main configuration, changing the PHP version or turning on HTTPS never overwrites them.

## Creating a file

1. Click **New file**.
2. Choose the **Domain**, and **where it goes** (inside the site block unless you know you need otherwise).
3. Enter a **Filename** ending in `.conf`, for example `uploads.conf`.
4. Write the **Content** and save.

### Example: a different upload limit for one site

The server-wide upload limit follows PHP's **Post max size** (see [PHP settings](/servers/php#php-settings)). To give one site its own limit, create `uploads.conf` **inside the site block**:

```nginx uploads.conf
client_max_body_size 256M;
```

PHP's limits still apply, so raise them on the server's PHP tab too.

### Example: proxy a WebSocket server

Create `websockets.conf` **inside the site block**:

```nginx websockets.conf
location /app/ {
    proxy_http_version 1.1;
    proxy_set_header Host $http_host;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "Upgrade";
    proxy_pass http://127.0.0.1:8080;
}
```

## Changes are checked before they go live

When you save, create, rename or delete a file, flitops writes it to the server and asks the web server to **test the whole configuration**. If the test fails (for example, a missing semicolon), flitops puts the previous version back and shows the error, so a typo can't take your site down. If it passes, the web server reloads gracefully, without dropping connections.

## Renaming and deleting

Hover a file and use **Rename** or **Delete**. Deleting removes the file from the server and reloads the web server. If another file still depends on it, the web server's check fails and the file is kept.

## History

Click **History** to see every change to the site's files: who made it, when, and what changed. Select an entry to see that version, and click **Restore this version** to put it back. A file that has been deleted can't be restored from history; create it again instead.

## Keeping in sync with the server

If someone edits the files directly on the server, the dashboard may show an older version. Click **Refresh** (or **Sync file contents from server**) to read the current files from the server.

## Tips

- Keep each file focused on one thing, with a clear name. It makes history easier to read.
- Configuration you add applies to the domain you chose. If the site has several domains, add the file to each one that needs it.
- Avoid repeating directives that flitops already sets in the main configuration; the web server will reject duplicates.
