---
title: "Source control"
description: "Connect GitHub, GitLab or Bitbucket so flitops can list your repositories and deploy your code."
---

A **source control account** is a connection to the service that hosts your Git repositories. flitops uses it to list your repositories and branches when you create a site, to give your servers permission to download your code, and to set up [Deploy on push](/sites/deployments#automatic-deploys).

Source control accounts belong to **you**, not to a team. Once connected, you can use the account in every team you're a member of.

## Supported providers

| Provider | Supported |
| --- | --- |
| **GitHub** | Repository and branch lists, deploys and Deploy on push |
| **GitLab** (gitlab.com) | Repository and branch lists (including projects in subgroups), deploys and Deploy on push |
| **Bitbucket** (Bitbucket Cloud) | Repository and branch lists, deploys and Deploy on push |
| **Any other Git host** | [Coming soon](/roadmap) |

## Connecting an account

<Steps>
  <Step title="Open Source Control">
    In the sidebar, click **Source Control**, then **Add Provider** and choose **GitHub**, **GitLab** or **Bitbucket**.
  </Step>
  <Step title="Approve access">
    The provider opens and asks you to approve flitops. Check the account shown is the one you want, then approve.
  </Step>
  <Step title="Return to flitops">
    You're sent back to flitops, and the account appears in the list with your username and email.
  </Step>
</Steps>

You can also connect an account while creating a site: click **Connect a provider** in the repository section. A new window opens for the approval, and what you've already filled in on the site form stays on the page.

### What flitops can do with your account

Whichever provider you use, flitops uses its access to:

- **Read your repositories and branches**, including private ones, so you can pick one and so your servers can download the code.
- **Read your profile**, to show which account is connected.
- **Add SSH keys to your account.** flitops adds each server's public key to your account, labelled with the server's name. That key is what lets the server download (clone) your private repositories. It's removed again when no site on that server uses the account any more, or when the server is deleted.
- **Add and remove webhooks** on repositories where you turn on Deploy on push.

GitLab and Bitbucket sign-ins expire after a couple of hours. flitops renews them automatically in the background. If renewing ever fails (for example, because you revoked flitops at the provider), flitops asks you to reconnect the account.

## Refreshing the repository list

flitops keeps a list of your repositories so the site form loads quickly. If you've just created a repository and it doesn't appear, use the reload button in the repository picker to fetch the latest list.

## Disconnecting an account

Click **Disconnect** next to the account. flitops forgets its access.

<Note>
  Disconnecting in flitops doesn't remove flitops from the provider. To fully revoke access, also remove flitops from the provider's list of authorised applications, and delete any server keys flitops added to your account for servers you no longer use:

  - **GitHub:** Settings → Applications → Authorized OAuth Apps, and Settings → SSH and GPG keys.
  - **GitLab:** Preferences → Applications, and Preferences → SSH Keys.
  - **Bitbucket:** Personal settings → App authorizations, and Personal settings → SSH keys.
</Note>

## Repository access tips

- The repository list shows every repository your account can access, including ones in organisations, groups and workspaces. If an organisation repository is missing on GitHub, the organisation may restrict third-party app access; an organisation owner can approve flitops in the organisation's settings.
- Because each server's key is added to your **personal** account, the server can download any repository you can. If you'd rather limit that, connect a separate account that only has access to the repositories you deploy.
